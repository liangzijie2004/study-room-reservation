## 一、项目概述

### 1.1 项目背景

高校图书馆与自习室座位资源紧张，"占座不来""一座难求"现象普遍。传统的人工登记方式效率低、无法实时反映座位占用情况，也难以约束违约行为。为此设计并实现一套校园共享自习室座位预约系统，将座位资源在线化、可视化，实现"线上选座、按时签到、超时释放"的闭环管理。

### 1.2 项目目标

1. 为师生提供便利的座位查询与预约入口，支持按日期、时段可视化选座；
2. 实现预约冲突的自动控制，保证同一座位同一时段不被重复预约；
3. 为管理人员提供自习室、座位、用户、预约、公告的统一后台管理能力；
4. 通过数据看板直观展示预约趋势与自习室热度，为资源调配提供依据。

### 1.3 项目意义

系统将线下座位管理搬到线上，提升座位周转率与利用率，减少因占座引发的矛盾；同时完整实践前后端分离架构、JWT 鉴权、分层设计与数据库设计等核心工程技能。

## 二、需求分析

### 2.1 角色分析

| 角色 | 说明 | 主要权限 |
|---|---|---|
| 学生（STUDENT） | 系统普通使用者 | 浏览自习室、预约座位、管理个人预约、查看公告、维护个人资料 |
| 管理员（ADMIN） | 系统运营者 | 自习室 / 座位 / 用户 / 预约 / 公告管理，查看数据看板 |

### 2.2 功能性需求

| 模块 | 需求描述 |
|---|---|
| 用户与认证 | 注册、登录、获取当前用户、修改资料、修改密码；登录状态基于 JWT 维持，接口按角色鉴权 |
| 自习室 | 学生浏览与搜索自习室；管理员增删改查 |
| 座位 | 管理员按行列批量生成座位网格、维护座位状态；学生查看座位图 |
| 预约 | 学生按"自习室 + 日期 + 时段 + 座位"预约，可取消 / 签到 / 签退；管理员查询并处理全部预约 |
| 公告 | 管理员发布 / 编辑 / 删除；学生查看 |
| 统计 | 管理员查看看板总览、近 N 天预约趋势、自习室预约排行 |

### 2.3 非功能性需求

- **安全性**：密码 BCrypt 加密存储；接口基于 JWT 鉴权；管理端接口按角色拦截。
- **一致性**：预约写入前进行时段冲突校验，避免超卖座位。
- **易用性**：座位图可视化，状态颜色区分；统一响应结构与友好错误提示。
- **可移植性**：默认 H2 内存库零配置运行，切换 MySQL 只需更换 profile。

### 2.4 核心用例：预约座位

1. 学生选择自习室 → 选择日期 → 选择固定时段；
2. 系统返回该自习室座位列表与已被占用座位号；
3. 学生点击可用座位并确认；
4. 系统校验时段合法性、座位归属与状态、座位冲突、用户时段冲突；
5. 校验通过则生成"已预约"记录，否则返回具体错误提示。

## 三、系统设计

### 3.1 总体架构

采用前后端分离的三层架构：

```
浏览器（Vue 3 单页应用）
        │  HTTP / JSON（Authorization: Bearer <token>）
        ▼
控制层 Controller  ←  JWT 拦截器（鉴权 / 角色校验）
        ▼
业务层 Service（事务、业务校验、冲突控制）
        ▼
持久层 Mapper（MyBatis-Plus）
        ▼
数据库（MySQL / H2）
```

- 前端通过 Axios 统一封装请求，响应拦截器解包 `data`，`401` 自动跳转登录；
- 后端统一返回 `{code, msg, data}`，异常由全局异常处理器兜底；
- 登录签发 JWT，拦截器解析令牌并把用户信息放入 `ThreadLocal` 上下文。

### 3.2 技术选型说明

| 技术 | 选型理由 |
|---|---|
| Spring Boot | 快速构建、生态成熟、内嵌 Tomcat 部署简单 |
| MyBatis-Plus | 简化单表 CRUD，内置分页与条件构造器 |
| JWT | 无状态鉴权，适合前后端分离与分布式扩展 |
| BCrypt | 自带盐值的自适应哈希，避免明文与彩虹表风险 |
| Vue 3 + Element Plus | 组件丰富、上手快，适合管理类系统快速开发 |
| ECharts | 图表能力成熟，满足看板可视化需求 |

### 3.3 模块划分

| 层次 | 包 / 目录 | 职责 |
|---|---|---|
| 控制层 | `controller` | 接收请求、参数校验、返回统一结果 |
| 业务层 | `service`、`service/impl` | 业务规则、冲突校验、数据组装 |
| 持久层 | `mapper` | 数据库访问 |

## 四、关键功能实现

### 4.1 JWT 登录鉴权

1. 登录成功后由 `JwtUtil` 使用 HMAC256 签发令牌，载荷包含 `userId`、`username`、`role`，有效期 24 小时；
2. 前端将令牌存入 `localStorage`，Axios 请求拦截器统一添加到 `Authorization: Bearer <token>`；
3. 后端 `JwtInterceptor` 拦截 `/api/**`（放行登录与注册），校验令牌并解析用户，写入 `UserContext`；
4. 标注 `@AdminOnly` 的接口（方法级或类级）在拦截器中校验角色，非管理员返回 `403`；
5. 令牌缺失或失效返回 `401`，前端拦截器捕获后清除令牌并跳转登录页。

### 4.2 预约冲突控制（核心）

创建预约时依次进行四重校验，全部通过才写入：

1. **时段合法性**：开始与结束时间必须属于系统固定时段（08:00-10:00 等 5 个时段）；
2. **对象有效性**：日期不得早于当天；自习室存在且开放；座位存在、属于该自习室且非维护中；
3. **座位冲突**：查询同一座位、同一日期、状态为"已预约/已签到"且时间区间重叠的记录，存在则拒绝；
4. **用户冲突**：同一用户在同一时段已存在其他预约时拒绝，避免重复占座。

时间重叠判断采用半开区间逻辑：`新开始 < 已有结束 AND 新结束 > 已有开始`，即视为重叠。该逻辑同时用于"查询某时段已被占用的座位号"，为前端座位图着色提供数据。

### 4.3 座位图可视化

- 座位表保存 `row_index`、`col_index`，前端使用 CSS Grid 按行列还原座位布局；
- 前端先取座位列表，再调用 `/api/reservations/seat-status` 获取已占用座位号，渲染为"可用 / 已占用 / 维护中"三态并附图例；
- 已占用与维护中的座位禁用点击，选中的座位高亮，底部实时显示"已选座位"。

### 4.4 签到与签退

- 仅"已预约"状态可签到，且必须在预约当天（避免无效签到），签到记录 `checkin_time`；
- 仅"已签到"状态可签退，签退后状态置为"已完成"并记录 `checkout_time`；
- 取消操作仅允许对"已预约"记录执行，且非本人操作会被拒绝。

### 4.5 数据看板

- 总览：统计用户数、自习室数、座位数、今日预约数，并按 `今日预约数 / 座位总数` 计算座位使用率（保留 1 位小数）；
- 趋势：按日期分组统计近 N 天预约量，服务端补齐缺失日期为 0，返回连续日期序列；
- 排行：按自习室分组统计预约量并倒序排列。

### 4.6 数据初始化

`DataInitializer` 在应用启动时检测到用户表为空，则自动写入演示数据：1 名管理员、2 名学生、4 个自习室、134 个座位、3 条公告以及近 7 天的预约记录（用于看板展示）。密码在运行期统一由 BCrypt 加密，避免脚本中硬编码哈希。

## 六、总结与展望

### 6.1 项目总结

本系统完成了从需求分析、数据库设计、接口设计到前后端编码与测试的完整流程，实现了"浏览—选座—预约—签到—签退"的业务闭环，并通过 JWT 鉴权、角色拦截、预约冲突控制、可视化座位图与数据看板，覆盖了课程实训的核心考查点。

### 6.2 不足与展望

1. **并发**：当前冲突校验为"查询后写入"，高并发下建议对座位加数据库唯一约束或分布式锁（同一座位同一日期时段唯一）；
2. **违约处理**：可增加定时任务，对逾期未签到的预约自动置为"违约"并限制预约次数；
3. **移动端**：可扩展微信小程序端，方便学生快速预约；
4. **消息通知**：可接入站内信或短信，在预约临近与违约前提醒用户。
